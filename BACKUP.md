# Бэкапы (Яндекс Диск)

Скрипт `scripts/backup.sh` создаёт архив PostgreSQL + media и загружает его через
rclone. Настройки находятся в существующем `/opt/archeology-site/.env`.

## Включение и период

```dotenv
BACKUP_ENABLED=1
BACKUP_SCHEDULE=monthly
```

- `BACKUP_ENABLED=0` — выключить. Ручной и старый cron-запуск завершаются успешно
  до создания файлов, вызова Docker/rclone и отправки писем.
- `BACKUP_ENABLED=1` — включить. При ошибке отправляется письмо на `BACKUP_ALERT_TO`
  (по умолчанию `7634216@gmail.com`), используя существующий `~/.msmtp-secrets`.
- `BACKUP_SCHEDULE=monthly` — `15 4 1 * *`, первое число каждого месяца, 04:15.
- `weekly` — `15 4 * * 1`, понедельник, 04:15.
- `daily` — `15 4 * * *`, ежедневно, 04:15.

Часовой пояс задаёт cron на ВМ: на действующей ВМ это UTC, то есть 07:15 по Москве.
Скрипт вручную запускается сразу независимо от периода, но соблюдает переключатель.
Если ключи отсутствуют, используются `BACKUP_ENABLED=1` и `BACKUP_SCHEDULE=monthly`.
Явно пустые или неизвестные значения переключателя/периода считаются ошибкой.

После изменения переключателя или периода синхронизировать реальное расписание
**от пользователя freeway, без sudo**:

```bash
ssh freeway@178.154.215.39
cd /opt/archeology-site
bash scripts/setup-backup-cron.sh
crontab -l
```

При включении установщик оставляет одну запись для этого проекта, заменяя старое
расписание. При выключении удаляет её. Остальные задания сохраняются. Повторный
запуск безопасен; некорректные настройки не меняют crontab. Не создавайте параллельно
другое задание или systemd-таймер. Отредактированный период применяется к cron после
запуска установщика; выключение дополнительно проверяется при каждом запуске бэкапа.

Необязательные настройки в том же `.env`:

| Ключ | По умолчанию |
| --- | --- |
| `BACKUP_DIR` | каталог `backups` в проекте |
| `BACKUP_LOG` | `$HOME/backup.log` |
| `BACKUP_KEEP` | 14 архивов на Диске |
| `BACKUP_RCLONE_REMOTE` | `yadisk` |
| `BACKUP_RCLONE_PATH` | `Archeology-site/backups` |
| `BACKUP_ALERT_TO` | `7634216@gmail.com` |

Значения с пробелами заключайте в одинарные или двойные кавычки. Эти скрипты читают
только перечисленные ключи и `POSTGRES_USER`/`POSTGRES_DB` как данные; shell-команды
и подстановки `${...}` в `.env` не исполняются. Экспортированное окружение имеет
приоритет над `.env`. Секреты rclone и SMTP остаются в существующих закрытых файлах.

## Настройка rclone

Установить rclone и настроить remote `yadisk` типа `yandex` с авторизацией по
[документации rclone](https://rclone.org/yandex/). Проверка без запуска бэкапа/почты:

```bash
rclone lsd yadisk:
rclone lsf yadisk:Archeology-site/backups/ --files-only
```

Если папки ещё нет, создать `rclone mkdir yadisk:Archeology-site/backups`.
После восстановления доступа включить `BACKUP_ENABLED=1`, установить cron и
выполнить ручной прогон, проверив появление нового архива на Диске.

На 2 ноября 2026 года действующая ВМ получает HTTP 410 GoneError и для корня
`yadisk:`, и для папки бэкапов. Последний плановый запуск 1 ноября создал локальный
архив и упал при `rclone copy`. Поэтому на ВМ установлены `BACKUP_ENABLED=0` и
`BACKUP_SCHEDULE=monthly`; активного cron бэкапов нет до восстановления доступа.
Эта запись описывает состояние на дату проверки, актуальное состояние — в `.env`.

## Ручной прогон и хранение

```bash
cd /opt/archeology-site
bash scripts/backup.sh
```

Лог: `~/backup.log`. Локальные архивы:
`/opt/archeology-site/backups/backup-YYYYmmdd-HHMMSS.tar.gz`.
Существующие локальные архивы и промежуточные файлы не удаляются автоматически,
в том числе при сбое загрузки. Их очистка — вручную после проверки удалённых копий
и свободного места. На Диске после успешной загрузки сохраняется прежняя ротация:
последние `BACKUP_KEEP` архивов. Выключение не удаляет архивы ни локально, ни на Диске.

## Восстановление

Скачать и распаковать нужный архив: внутри `db.sql` и `media.tar.gz`.
Команды ниже перезаписывают данные; выполнять только при намеренном восстановлении.

```bash
cd /opt/archeology-site
# БД: сначала подготовить целевую БД согласно плану восстановления.
docker compose exec -T db psql -U archeology -d archeology < db.sql
# Медиа:
docker compose run --rm --no-deps \
  -v "$PWD:/restore:ro" \
  web \
  tar -xzf /restore/media.tar.gz -C /app
```
